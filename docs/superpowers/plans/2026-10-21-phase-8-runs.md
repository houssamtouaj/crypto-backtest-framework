# Phase 8 — Runs: working plan

Spec: `docs/superpowers/specs/2026-09-26-ob-backtest/phase-8-runs.md` with `00-overview.md`.
Branch: `phase/8-runs` from `dev` at cbfb560 (Phase 7 merge). This phase produces no code. A
bug found at the review gate is the only reason to touch `perpbt/`.

Stops for the user (each one is irreversible or outward-facing):
S1 data refresh or keep, plus `data_download_date` / `holdout.end`; S2 freeze, commit and tag;
S3 review gate after steps 3–4; S4 holdout; S5 merge into dev and the dev → main PR.

## Facts carried in (memory)

- Fetch one pair at a time (`--pairs X`) in the background: a full three-pair fetch runs the machine
  short of memory. Add `--ccxt-gaps` for SOLUSDT; it is once per gap and the two known gaps are
  already recorded.
- `data_download_date` must be set before `prereg freeze`. `holdout.end` must not be after it, and
  the holdout runner checks `holdout.end` against the date in the lock.
- Period ends are inclusive; the loader reads to `end + 1 day`. The download day is partial (the
  tail stops at fetch time), so `holdout.end` = download date − 1 gives a holdout of whole UTC days.
- Grid on 4 workers (worker peak RSS 0.73 GB, ~5 GB free).
- `perpbt/report/` is outside the code version (D15). A report fix after the freeze is not a
  holdout code change; a fix anywhere else in `perpbt/` is.
- Do not edit `perpbt/` while a run is in progress (the code version would change mid-run).

## Steps

0. Preconditions (§8.1): fast tests green on `dev`; slow tests green once on real data (Phases
   1–7 ran them); `git status` clean; ≥ 3 GB free on D: (8.1 GB measured).
   `.gitignore` has `/runs/`, which hides the directory, so step 7's files cannot be committed.
   Change it to `/runs/**` with negations for `runs/summary.md`, `runs/registry.jsonl`,
   `runs/results.parquet` and the nine primary `report.md` files.
1. Data (S1). If refreshing: `perpbt data fetch --pairs P --ccxt-head --ccxt-tail` per pair
   (SOLUSDT with `--ccxt-gaps` as well), in the background, then `perpbt data validate`. Read the
   gap and 1m→15m counts in every manifest and compare them with the 2026-09-27 values (BTC 18,
   ETH 18, SOL 22 mismatching candles; 0 gaps). Commit the manifests. Set
   `data_download_date` and `holdout.end` in `configs/prereg.yaml` (and `holdout_end` in
   `configs/data.yaml`).
2. Freeze (S2). `perpbt prereg validate`, then `perpbt prereg freeze`. Commit `prereg.yaml` and
   `prereg.lock` together as "Freeze pre-registration" and tag `prereg-v1`.
3. In-sample primary. `perpbt run --primary`, `perpbt baselines --primary --runs 5000`,
   `perpbt stats holm`, `perpbt report`. Record runtimes.
4. Grid. `perpbt grid --run --workers 4`, `perpbt baselines --grid --runs 500`,
   `perpbt stats dsr`, `perpbt report --grid`. Record runtimes. If the grid exceeds 2 h, the
   signal-stream cache comes first (overview §9.3).
5. Review gate (S3). Read the nine primary reports and the heatmaps. Run the §8.3 greps
   (`allow_holdout=True` outside `experiments/holdout.py`; `read_frame` outside `perpbt/data/`
   and `tests/`). Check the registry for failed rows, the trade counts, fill rates, skip counts,
   cost-in-R, and the Holm and DSR blocks. Show the user the headline numbers. A bug fix is
   committed with a test, and steps 3–4 are rerun. The primary parameters and the verdict rule
   stay as they are.
6. Holdout (S4). `perpbt holdout`, with `--allow-code-change --reason "..."` only if step 5
   changed `perpbt/` outside `report/`.
7. Summary. `perpbt report`. Commit `runs/summary.md`, the nine primary `report.md` files,
   `runs/registry.jsonl` and `runs/results.parquet`. Show the user `runs/summary.md`.
8. Merge (S5). `git merge --no-ff phase/8-runs` into `dev`, delete the branch, push, open the
   `dev` → `main` PR.
